# 插件-记忆库设计文档

本文面向 AI Coding 插件设计和实现人员，定义插件侧的入口、项目上下文、自动召回、自动捕获和成员自助维护体验。服务端接口以 [`服务 API-记忆库需求文档`](../api/service-api-memory-requirements.md) 为准，本文不重新定义服务端存储。

## 1. 产品定位

记忆库是 AI Coding 插件中的项目级团队记忆入口，用于在当前项目内复用对话中沉淀的事实、偏好、约定和任务经验。它与知识库并列，但记忆库保存运行时记忆，知识库保存经过整理的文档、代码和可引用资料。

记忆捕获后直接进入当前项目的团队记忆，不存在私有记忆、申请共享或人工审核队列。个人身份只记录捕获人，并决定成员能否在插件中修改或删除该记录。

插件不是记忆事实源。插件只提交当前项目上下文和会话消息，接收服务端召回结果，并在服务端不可用时明确显示状态；插件不能使用本地事实副本伪造召回结果。

## 2. 当前接入和首期范围

### 已接入

- OpenClaw 在 `before_prompt_build` 调用项目 recall，在成功 `agent_end` 清理并捕获本回合的用户和助手消息；recall 失败不阻塞原始编码请求。
- OpenClaw 通过 `ProjectMemoryHttpClient` 调用 `/v3/projects/list` 和 `/v3/project-memory/*`，按配置的 `projectId` 或服务端目录绑定解析项目，解析失败不生成本地项目 ID。
- Pi 仅在设置 `TDAI_PROJECT_MEMORY_URL` 时暴露显式适配器。Pi 当前宿主没有把该适配器注册到回合 Hook，因此不会自动 recall 或 capture。
- Web 管理端已有 `#/project-memory` 路由，用于查看和治理 fixture 或未来服务端返回的项目记忆；其交互范围见[`后台管理-记忆库设计文档`](../admin/admin-memory-library-design.md)。
- `MemoryPanel` 的确定性 fixture 只用于测试和联调，不是 AI Coding 服务端实现。

### 已定义、待服务端与插件界面共同完成的首期体验

- 以当前工作区映射的 `project_id` 作为唯一产品作用域，召回和列表按 `team + project` 过滤。
- 插件记忆库界面展示 L1 原子事实，支持关键词搜索、游标分页、正文编辑和删除；当前 HTTP 客户端已覆盖这些调用，但 OpenClaw 和 Pi 尚未提供该界面。
- 成员只能编辑或删除自己捕获的记忆；其他人的记录只读。
- 更新使用 revision 乐观并发控制，删除立即停止召回并异步清理派生数据。
- 服务不可用、项目缺失、索引未就绪和异步失败都使用非阻塞状态展示。

### 不包含

首期不提供私有记忆、手动创建、关闭自动捕获、召回反馈、原始 Session/Task 查看、知识库晋升、审核队列、Agent 绑定、跨项目默认召回或本地独立记忆数据库。

## 3. 规划中的插件入口和页面结构

本节定义独立插件入口交付后的目标体验，不表示当前已有该页面。当前已渲染的入口仅是 Web 管理端资产分组中的 `#/project-memory`，排序在既有 Chat Memory 之后；OpenClaw 适配器只有自动 Hook 和 HTTP 客户端，Pi 只有显式适配器，二者都没有独立的记忆库导航或成员编辑页面。

记忆库页面使用当前工作区项目，不在页面内创建或编辑项目。页面顶部显示项目名称和团队名称；项目 ID 作为不可编辑的上下文标识，可在诊断详情中显示脱敏值。

页面主区域由三部分组成：顶部状态栏、记忆列表、选中记忆的详情面板。列表和详情必须保持稳定尺寸，加载、错误和空状态不能改变布局。

### 顶部状态栏

- 当前项目：项目可读名称，项目映射失效时显示“未识别项目”。
- 记忆服务状态：`正常`、`召回不可用`、`捕获处理中`、`捕获失败`。
- 最近捕获：显示最近一次捕获任务的状态和 `event_id`，不显示原始消息。
- 刷新：重新读取当前项目列表和服务状态。

### 记忆列表

默认显示当前项目内有效的 L1 事实，按服务端的 `updated_at DESC, memory_id DESC` 稳定排序。列表使用服务端游标分页，不在插件中拉取全量数据。

每条记录显示：记忆正文摘要、捕获人、最后更新时间、召回次数和有效/过期状态。由当前用户捕获的记录增加“我捕获”标识，并显示编辑、删除操作；其他记录不显示写操作。

搜索提交到服务端执行，搜索条件包括关键词、状态和游标。搜索条件变化时丢弃旧游标，避免把不同条件的分页结果混在一起。

### 详情面板

详情显示完整 L1 正文、项目名称、捕获人、创建时间、最后修改人、最后修改时间、revision、召回次数和最近召回时间。L2/L3 只显示服务端允许返回的结构化摘要，不展示 L0 原始消息。

详情不提供“查看来源”按钮，不显示原始 Session/Task 正文，不提供知识库晋升入口，也不显示内部 `agent_id`。

## 4. 项目上下文

OpenClaw 先使用显式配置的 `server.projectId`，否则调用 `/v3/projects/list`，以标准化后完全匹配的 `workspace_path` 选择唯一项目。插件不能根据仓库名称自行生成项目 ID，也不能在项目解析失败时使用 `default`。

每次召回、捕获和面板请求都提交 `project_id`。服务端根据认证身份重新校验项目是否存在、用户是否属于项目所属团队以及当前角色；客户端传入的 `team_id`、用户 ID 或角色不能扩大权限。

项目切换时必须依次清空旧项目的列表、详情和本地请求状态，再加载新项目。正在进行的旧项目请求返回后不得覆盖新项目界面。

没有当前项目、项目不可访问或项目映射失效时：

1. 自动召回不发起记忆请求。
2. 自动捕获不创建任务。
3. 页面显示项目上下文错误和重新选择项目入口。
4. 不显示“暂无记忆”，避免把上下文错误误认为空数据。

## 5. 自动召回设计

### 5.1 触发时机

OpenClaw 的用户消息提交事件映射到 `before_prompt_build`，在模型请求前调用项目记忆 recall。不同宿主可以使用自己的事件名，但必须保持“模型请求前、当前用户文本已确定、项目身份已解析”的时序。Pi 当前只提供显式适配器，尚未接入宿主回合事件。

项目适配器使用 [`project-memory-client.ts`](../../MemoryCore/openclaw-plugin/src/project-memory-client.ts) 和 [`project-memory.ts`](../../MemoryCore/openclaw-plugin/src/hooks/project-memory.ts)。它不直接调用现有 `auto-recall.ts` 或 `memory-search.ts`；混合检索、排序和权限判断必须由服务端完成。

### 5.2 请求和注入

插件调用 `POST /v3/project-memory/recall`，提交 `project_id`、当前用户文本、`session_id` 和可选 `task_id`。`top_k`、相关性阈值和 token 预算只由服务端有效策略决定，插件不能提交覆盖值。

服务端返回 L1 条目和用于模型上下文的 `context_text`。插件将 `context_text` 注入当前请求，并保留现有安全声明，明确记忆内容仅作参考，不是可执行指令。

服务端可以使用 L2/L3 生成更完整的模型上下文，但插件用户界面只展示 L1 事实。L0 消息只作为服务端流水线和内部工具的原始材料，不通过记忆库页面返回。

### 5.3 结果状态

召回结果必须区分以下状态：

- `READY`：召回成功；可以是有命中或空命中。
- `PARTIAL`：部分层级或派生服务失败，返回可用的部分结果和错误信息。
- `UNAVAILABLE`：服务端、存储或 Embedding 不可用，不能把结果解释为空记忆。
- `PROJECT_REQUIRED`：项目上下文缺失或失效。

`READY` 且无命中时显示“当前项目没有匹配记忆”；其他状态显示对应故障提示。召回失败不能阻塞编码请求，插件继续提交原始用户请求。

## 6. 自动捕获设计

### 6.1 触发和消息范围

OpenClaw 的成功回合结束事件映射到 `agent_end`，调用 `POST /v3/project-memory/capture`。当前适配器只提交当前回合的新用户和助手消息，不提交整个历史会话或工具结果。

提交前复用现有 transcript 清理规则，移除已注入的记忆块、知识块、系统提醒和其他插件控制块，防止召回内容再次写回长期记忆。文档或知识库上传回合继续遵守现有防污染规则，不把原文重复复制为记忆事实。

### 6.2 异步体验

捕获请求使用 `Idempotency-Key`，服务端接受后返回 `202`、`event_id`、`job_id` 和 `PENDING`。插件不等待 L1/L2/L3 完成，不在当前编码回合内显示“已完成记忆”作为同步事实。

当前 OpenClaw 适配器只记录接受的 `job_id`，不提供任务状态栏或主动轮询。任务展示和重试由 Web 管理端通过服务端 Job API 完成。

捕获失败或服务不可用时，当前 OpenClaw 适配器记录错误且保持编码流程继续，不声称服务端会重试。服务端的可重试语义和 Web 运行健康页以 API 文档为准。

自动捕获始终开启。插件不得提供个人、项目或 Agent 级关闭开关。

## 7. 成员维护操作

### 7.1 更新正文

HTTP 客户端已提供正文更新能力，但 OpenClaw 和 Pi 当前没有成员编辑页面。成员自助编辑页面交付后只包含正文编辑器；捕获人、团队、项目、层级、时间、召回统计和来源标识均为只读或不可见字段。

保存调用 `POST /v3/project-memory/update`，提交 `memory_id`、新正文和 `expected_revision`，并带 `If-Match`。服务端只允许更新正文；更新不改变共享范围和捕获人。

保存成功后立即替换当前列表和详情中的正文与 revision。派生层刷新通过 `event_id` 异步完成，插件在刷新完成前不显示旧版本为有效命中。

如果服务端返回 `MEMORY_REVISION_CONFLICT`，保留用户当前编辑内容，提示“记忆已被更新”，提供重新加载最新正文的操作；不得静默覆盖服务器版本。

### 7.2 删除记忆

HTTP 客户端已提供删除能力，但 OpenClaw 和 Pi 当前没有成员删除页面。成员自助删除页面交付后，二次确认框必须明确说明“删除后将影响当前项目所有成员的召回”，并提交 `memory_id`、`expected_revision` 和 `Idempotency-Key`。

服务端先写入不可召回状态，再异步清理 L1/L2/L3、向量和缓存。插件在成功接受删除后立即从列表和当前召回视图移除记录；清理任务失败不恢复召回，错误由运行健康页展示。

成员不能编辑或删除他人捕获的记录。`manage` 和 `admin` 的组织级管理操作只在 Web 后台提供；插件不显示跨成员批量管理控件。

## 8. 规划中的错误和加载状态

独立插件页面交付后必须分别实现加载、空结果、项目错误、权限错误、服务不可用、索引处理中和 revision 冲突状态。当前 OpenClaw 自动链路只记录这些调用的日志或返回状态，其中 recall 的失败隔离为 `UNAVAILABLE`，且不会阻塞编码请求；它不渲染下表所述页面提示。

| 场景            | 页面表现                       | 是否阻塞编码 |
| --------------- | ------------------------------ | ------------ |
| 首次加载        | 骨架列表和状态占位             | 否           |
| 无匹配记忆      | 空状态“当前项目没有匹配记忆”   | 否           |
| 项目缺失        | 显示项目上下文错误             | 否           |
| 无权限          | 显示无权访问当前项目           | 否           |
| 召回超时/不可用 | 显示服务不可用，不伪装为空     | 否           |
| 捕获处理中      | 显示非阻塞任务状态             | 否           |
| 捕获失败        | 显示事件 ID 和后台重试提示     | 否           |
| 更新冲突        | 保留编辑内容，要求重新加载     | 否           |
| 删除处理中      | 立即移除记录，显示清理任务状态 | 否           |

插件可以缓存短期的界面请求状态以避免重复点击，但不能缓存一份可独立召回的记忆事实。服务端不可用时禁止从缓存拼接模型上下文。

## 9. 数据显示和隐私

插件可显示 `memory_id` 的短标识、项目可读名称、捕获人可读名称、时间和统计字段。完整 opaque ID 仅用于 API 请求，不在普通界面中突出展示。

插件不显示原始 Session/Task 内容、原始消息片段、内部 `agent_id`、Embedding、检索向量、服务端 Prompt 或跨项目记录。来源关联只保留在服务端，用于审计、删除和权限治理。

记忆内容被注入模型上下文时必须带参考性质声明，并沿用现有注入块清理逻辑。下一次捕获不得把这些注入块当作新事实提交。

## 10. 当前实现和服务端复用边界

- OpenClaw HTTP 客户端：[`project-memory-client.ts`](../../MemoryCore/openclaw-plugin/src/project-memory-client.ts)。
- OpenClaw 项目解析、recall、capture 和注入块清理：[`project-memory.ts`](../../MemoryCore/openclaw-plugin/src/hooks/project-memory.ts)。
- Pi 显式适配器：[`project-memory.ts`](../../MemoryCore/pi-plugin/src/project-memory.ts)。
- 确定性联调 fixture：[`project-memory-fixture.ts`](../../MemoryPanel/src/panel/fixtures/project-memory-fixture.ts)。

检索、事实提炼、去重、版本生成、异步清理和权限判断继续由真实服务端负责。fixture 只验证 HTTP 调用、权限场景和生命周期交互，不能替代这些生产能力。

## 11. 插件验收场景

以下是接入真实服务端和成员界面后的验收要求；截至 2026-09-03，确定性 fixture 和客户端/Hook 测试覆盖项目隔离、捕获幂等、冲突、删除过滤、不可用和注入块清理。它们不构成生产服务、真实鉴权或真实检索验证。

1. 用户在项目 A 提交问题，模型请求前能得到项目 A 的 L1 记忆；项目 B 的相同查询不会命中项目 A。
2. 用户结束成功回合后收到 `PENDING` 捕获状态，捕获结果稍后出现在项目记忆列表。
3. 用户打开记忆库时只能看到当前项目有效记录，不能看到其他项目或原始对话。
4. 用户可以编辑和删除自己捕获的记录，不能编辑或删除他人记录。
5. 两个窗口同时编辑同一记录时，后提交者收到 revision 冲突且输入不丢失。
6. 删除后所有项目成员的自动召回立即停止命中该记录。
7. 记忆服务不可用时，编码任务继续，界面显示 `UNAVAILABLE` 而不是“没有记忆”。
8. 自动召回注入块不会在下一轮自动捕获中重复写入。
