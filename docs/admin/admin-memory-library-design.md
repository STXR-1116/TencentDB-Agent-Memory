# 后台管理-记忆库设计文档

本文面向 Web 管理后台产品、交互和前端实现人员，定义项目级团队记忆的页面结构、权限、筛选、编辑、项目调整、策略、任务和审计。后台调用的接口以 [`服务 API-记忆库需求文档`](../api/service-api-memory-requirements.md) 为准。

## 1. 后台职责

后台负责组织范围内团队记忆的治理和运行状态管理，不执行模型推理，不直接读写 MemoryCore 的本地文件，不绕过 AI coding 服务端。服务端是记忆内容、权限、版本和任务状态的唯一事实源。

首期不提供审核队列、私有记忆、知识库晋升、Agent 绑定、手动创建记忆、原始对话查看或项目生命周期管理。自动捕获的记忆直接可用；后台通过权限、正文修订、删除、项目调整、策略和审计完成治理。

## 2. 角色模型

| 角色     | 记忆读取         | 编辑/删除        | 项目调整 | 策略               | 任务               |
| -------- | ---------------- | ---------------- | -------- | ------------------ | ------------------ |
| `member` | 自己有权限的项目 | 无后台写权限     | 无       | 只读生效策略       | 只看自己请求的状态 |
| `manage` | 所属组织项目     | 所属组织全部记忆 | 所属组织 | 组织默认和项目覆盖 | 查看/重试所属组织  |
| `admin`  | 全部组织项目     | 全部组织记忆     | 全部组织 | 全局、组织和项目   | 查看/重试全部组织  |

角色由服务端认证上下文决定。前端隐藏按钮只改善体验，不构成授权；任何页面请求都必须让服务端重新校验组织、团队、项目和角色。

## 3. 信息架构

目标信息架构包含以下四个治理视图：

1. **团队记忆**：记忆列表、详情、正文编辑、删除和项目调整。
2. **记忆策略**：全局/组织/项目策略的生效值、继承关系和修改。
3. **运行健康**：召回、捕获、索引刷新、删除清理任务和重试。
4. **记忆审计**：记忆版本和治理操作的审计查询。

截至 2026-09-03，Web 已交付单一 `#/project-memory` 路由，以四个页签承载上述视图，不是四个独立页面。它已通过 Panel 的 `/api/v1/project-memory/*` 转发调用项目目录、列表、正文更新、删除、项目调整、项目策略、任务和审计接口；列表支持项目、组织、团队和关键词条件、服务端游标及旧请求丢弃。详情直接使用当前列表项，尚未调用 `get`，也没有 L2/L3 懒加载、版本时间线、来源摘要、完整筛选条件或任务/审计的服务端筛选与游标。

前端按项目目录返回的角色隐藏治理操作，但授权仍必须由服务端执行。当前页面对 `manage/admin` 开放正文更新、删除、项目调整、项目级 `top_k` 更新和可重试任务；`member` 只读。该可见性不是生产鉴权证据，确定性 fixture 才为当前联调提供相应的 403、409、503 和删除过滤场景。

现有 Chat Memory 页面可复用列表/详情布局、响应信封、团队切换和懒加载层级组件，但应移除 Agent 固定资产、分配 Agent、解绑、私有范围切换和手工创建资产的控件。知识库、Wiki、CodeGraph 和 Skill 页面不因本设计改变其 Agent 装配功能。

## 4. 团队记忆页面目标

### 4.1 页面头部

头部显示当前组织、团队和项目选择器。团队选择器沿用现有全局团队切换；项目选择器只显示服务端返回的当前用户可访问项目。

头部右侧显示：

- 当前项目有效记忆数量的估计值。
- 最近捕获、更新和清理任务状态。
- 刷新按钮。

不存在当前项目时，页面显示项目上下文错误，不请求默认项目，不显示空列表。

### 4.2 筛选工具栏

支持以下服务端筛选：

- 项目：当前项目或组织范围内的项目（`manage/admin`）。
- 关键词：对 L1 正文执行服务端搜索。
- 捕获人：按用户选择。
- 时间范围：创建时间或更新时间。
- 层级：默认 L1，可切换 L2/L3 详情查询；L0 不作为正文列表层级。
- 状态：有效、处理中、已过期、已删除。默认只显示有效记录。

筛选条件变化时清空游标并重新请求第一页。分页使用服务端 `next_cursor`，禁止前端拉全量再过滤。列表排序固定为 `updated_at DESC, memory_id DESC`，确保插入和更新不会造成重复或跳页。

### 4.3 列表列

默认列为：

| 列       | 展示                                |
| -------- | ----------------------------------- |
| 内容     | L1 正文，超长截断，详情查看完整文本 |
| 项目     | 项目名称；组织范围视图必显示        |
| 捕获人   | 用户可读名和“我捕获”标识            |
| 层级     | L1；详情可展开 L2/L3                |
| 重要度   | 服务端计算值，只读                  |
| 召回次数 | 统计值，只读                        |
| 最近召回 | 时间或“未召回”                      |
| 更新时间 | 最后正文版本更新时间                |
| 状态     | 有效、过期、删除中、已删除          |
| 操作     | 查看；有权限时编辑、删除、调整项目  |

列表不展示 Agent、原始消息、Session/Task 正文、Embedding 或知识库对象 ID。

### 4.4 详情抽屉

详情抽屉分为“内容”和“治理信息”两组：

- 内容：完整 L1 正文；L2/L3 使用懒加载切换，返回为空时明确显示“暂无该层级内容”。
- 归属：组织、团队、项目名称和 opaque ID 的短标识。
- 责任：捕获人、最后修改人、创建时间、更新时间。
- 质量/使用：重要度、召回次数、最近召回时间、当前状态。
- 版本：当前 revision、版本变更时间线和每次操作结果。
- 来源摘要：来源类型、脱敏 Session/Task 标识和时间；不提供原始正文查看。
- 异步任务：相关捕获、刷新、删除任务的状态和 event ID。

详情接口必须按当前操作者重新鉴权。前端不能通过修改 URL 或 `memory_id` 读取其他组织的记录。

### 4.5 编辑正文

编辑弹窗只允许修改正文。以下字段不可编辑：捕获人、组织、团队、项目、层级、重要度、召回统计、来源标识、创建时间和 revision。

保存时提交当前 revision，使用 `If-Match` 和 `expected_revision`。成功后详情立即显示新正文和新 revision，并显示派生层刷新任务。收到 `MEMORY_REVISION_CONFLICT` 时保留编辑内容，显示服务端最新正文和“重新加载后继续编辑”操作，禁止覆盖保存。

`member` 不显示后台编辑入口。`manage` 可编辑所属组织记录，`admin` 可编辑所有组织记录。编辑只能通过正文更新接口完成，不能借此改变项目归属。

### 4.6 删除记忆

删除弹窗必须显示：记忆正文摘要、项目名称、捕获人和“删除后将影响当前项目所有成员的召回”。确认后提交 revision 和幂等键。

服务端接受删除后立即将记录标记为不可召回，后台异步清理 L1/L2/L3、向量和缓存。列表立即移除有效记录，运行健康页显示清理任务。清理失败不会自动恢复召回；只有明确的管理员恢复流程（首期不提供）才能改变状态。

### 4.7 调整项目归属

`manage/admin` 可打开“调整项目”弹窗，选择目标项目并确认影响范围。调整项目不是正文编辑，必须使用独立接口和审计事件。

调整成功后：

1. 原项目立即停止召回和列表展示。
2. 新项目记录进入 `INDEX_PENDING` 或有效状态，取决于派生索引状态。
3. 捕获人保持不变。
4. 内容、revision 和版本历史保持不变。
5. 相关项目的列表和统计在下一次刷新后更新。

## 5. 记忆策略页面目标

### 5.1 继承层级

策略有全局、组织和项目三层：

- `admin` 设置全局默认值和硬上限。
- `manage` 设置所属组织默认值和组织项目覆盖值。
- 项目值只能在全局硬上限内收紧，不得放宽。
- `member` 只能查看其当前项目的生效策略。

每个字段同时显示“生效值”和“来源”：继承、组织覆盖或项目覆盖。保存前显示将生效的范围和受影响项目。

### 5.2 首期策略字段

| 字段                  | 作用                 | 约束                                 |
| --------------------- | -------------------- | ------------------------------------ |
| `recall_scope`        | 当前项目召回范围     | 首期固定 `project`，不允许跨项目     |
| `top_k`               | 自动召回最多返回条数 | 项目值不能超过全局上限               |
| `relevance_threshold` | 最低相关性           | 项目只能提高阈值                     |
| `token_budget`        | 注入模型上下文预算   | 项目不能超过全局上限                 |
| `l0_retention_days`   | L0 默认保留期        | 默认 30 天，项目不能超过全局允许范围 |
| `auto_capture`        | 是否自动捕获         | 固定为 `true`，不可关闭              |

策略更新要求 `expected_revision`，成功后返回新 revision 和配置发布任务。策略接口必须返回每个字段的来源层级，不能只返回合并后的匿名对象。

## 6. 运行健康页面目标

运行健康页面按任务类型分组：召回请求、自动捕获、索引刷新、正文更新派生、项目调整和删除清理。

每条任务显示：`job_id`、`event_id`、组织/团队/项目、任务类型、状态、创建时间、开始/结束时间、重试次数、错误码、错误摘要和结果引用。错误摘要不能包含 Token、原始消息或敏感正文。

状态为 `PENDING/RUNNING/SUCCEEDED/FAILED/CANCELLED`。只有 `FAILED` 且服务端标记可重试的任务显示“重试”；重试提交幂等键并生成新的尝试记录，不覆盖原始错误。

`manage` 只能查看和重试所属组织任务，`admin` 可跨组织。`member` 只能查看自己请求产生的任务摘要，不能重试。

## 7. 审计页面目标

审计页支持按组织、团队、项目、操作人、角色、操作类型、时间和结果筛选，使用服务端游标分页。操作类型包括：`CAPTURE_ACCEPTED`、`MEMORY_UPDATED`、`MEMORY_DELETED`、`SCOPE_MOVED`、`POLICY_UPDATED`、`JOB_RETRIED` 和 `INDEX_REFRESHED`。

每条记录显示操作时间、操作者、角色、记忆 ID、旧/新 project ID、旧/新 revision、结果、request ID、event ID 和错误码。审计页不展示原始对话正文，不保存前端提交的完整消息。

详情抽屉可查看同一记忆的版本时间线。版本内容是否展示遵循当前角色和组织权限；首期建议显示正文差异摘要，不提供跨组织对比。

## 8. 空、错和危险状态目标

| 状态       | 展示                       | 操作                |
| ---------- | -------------------------- | ------------------- |
| 无项目     | “未识别项目，无法加载记忆” | 选择项目            |
| 无权限     | “无权访问该项目”           | 返回可访问项目      |
| 无记忆     | “当前筛选条件没有记忆”     | 修改筛选            |
| 索引处理中 | “记忆已接受，索引处理中”   | 查看任务            |
| 服务不可用 | “记忆服务不可用”           | 刷新或查看健康      |
| 版本冲突   | “记录已被其他人更新”       | 查看最新、重新编辑  |
| 删除处理中 | “已停止召回，正在清理”     | 查看任务            |
| 删除失败   | “清理失败，召回仍保持关闭” | `manage/admin` 重试 |

任何服务端错误都不能在前端被转换为空列表。危险操作必须在确认框中显示影响项目和记录数量；批量删除首期不提供，避免把共享删除误操作扩大。

## 9. 组件复用和拆分

建议复用现有 `MemoryPanel/web` 的：

- `TeamSwitcher` 和团队会话上下文。
- `AssetPageHeader`、`AssetSplitLayout`、`AssetListPanel` 和详情抽屉布局。
- `chatMemoryApi` 的响应信封、错误转换和懒加载模式，但替换为 `/v3/project-memory/*` 客户端。
- `useCurrentRole`、权限显示和成员名称解析。

目标形态建议新增独立组件；当前实现尚未完成此拆分，而是由 `ProjectMemoryPage` 统一维护四个页签的状态：

- `ProjectMemoryPage`：页面状态和筛选协调。
- `ProjectMemoryList`：游标分页和列表行。
- `ProjectMemoryDetail`：内容、治理信息、版本和任务。
- `ProjectMemoryEditDialog`：正文和 revision 冲突。
- `ProjectMemoryScopeDialog`：项目调整。
- `MemoryPolicyPage`：继承策略编辑。
- `MemoryJobsPage`：任务查询和重试。
- `MemoryAuditPage`：审计筛选和版本时间线。

这些组件不实现事实提炼、向量搜索、权限计算、异步重试或本地持久化事实。

## 10. 后台验收场景

以下为接入真实服务端后的验收要求，不应以当前 fixture 或页面存在替代。当前 fixture 不提供生产持久化、模型、向量检索、生产认证或异步工作者，只验证固定数据和 HTTP 生命周期交互。

1. `manage` 登录后只能看到所属组织的项目和记忆，切换组织不能读取其他组织。
2. `admin` 能跨组织筛选和治理，但每次操作仍显示目标组织和项目。
3. 列表筛选、排序和游标由服务端执行，刷新不会重复或跳过记录。
4. 成员不能在后台编辑或删除记录；其插件写操作权限由服务端控制。
5. 正文更新产生新 revision，旧版本可在审计时间线看到，冲突不会覆盖内容。
6. 删除确认明确提示共享影响，成功后立即停止召回并显示清理任务。
7. 项目调整不修改正文和捕获人，旧项目立即停止命中，新项目显示索引状态。
8. 策略页面正确显示全局、组织、项目的生效值和来源，项目不能放宽上限。
9. 运行健康页可以查询失败任务并按角色重试，错误信息不泄露消息正文。
10. 审计页能追踪谁在何时修改了哪条记忆、从哪个项目移到了哪个项目。
